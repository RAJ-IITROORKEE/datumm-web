# DATUMM product UI audit and proposed next plan

13 November 2026. Branch: `codex/ui-ux-foundation-2026-11-12`.

**Verdict: the affectUI foundation is implemented, but the complete Revit playground experience is not.** Previous technical passes and selected browser checks did not establish complete Thread / Tasks / Memory / Agents / Permissions parity or a reliable concept-to-revision journey. Those broad completion statements are superseded by this product audit. This pass changes documentation only. Further application and backend development awaits review of the proposed work below.

The audit combined two independent Terra 6.1 High source reviews, Astra High first-party research, and parent-operated Codex browser inspection. It is not a new formal EGM Goldfish convergence run or an accessibility certification. Sources: [chat audit](audit-chat-product-2026-11-13.md), [viewer audit](audit-viewer-product-2026-11-13.md), [BIM research](audit-bim-research-2026-11-13.md). PLAN.md's Component reference map remains canonical; the approved EGM baseline is retained with an audit addendum.

## Decisions confirmed during this audit

1. Dark drafting canvas for everyday 2D/3D work, with a separate white Sheet/Print view.
2. **Generate → review → revise a concept** is the primary first-use web journey. Import/model review and connected automation remain secondary paths to plan separately.
3. Project-level **Brief & decisions** comes before personal memory across all chats: units, footprint, orientation, room needs, confirmed choices, visible sources and editable entries. This is a product direction, not evidence that editing/persistence APIs already exist.
4. **Compact project-centered navigation:** retain the four right-side tabs, use Running / Needs your input filters in the project task/chat overview, and place Brief & decisions under Project context. Separate top-level Tasks and Memory screens are not the selected direction. This confirms placement, not implementation approval for the proposed packages.

Retain the existing single-sidebar shell, stable chat and right Design / Activity / Assets / Exports area, explicit Ask / Plan / Build, grouped questions, draft-only suggestions, review/annotation rather than direct wall editing, and exact native approvals. Preserve affectUI theme/Inter; the drafting canvas is a purpose-specific surface, not a new application-wide theme.

## Proposed next development plan — not yet approved for execution

The four direction decisions above are confirmed. The following packages and their detailed controls are recommendations to review before implementation. They do not authorize backend changes or deployment.

**Dependency gate before development planning:** retain the reproduced failure and establish which deployed fields bind the confirmed brief, question receipts, outcome, artifact and recovery action. Decide explicitly whether a request is a provisional concept or site-specific/compliance work; do not silently change that scope. This gate is contract/research work, not authorization to edit or deploy the backend. UI-only polish may proceed after approval, but it cannot qualify concept generation while the service journey remains blocked. Validation must run throughout the packages below, not wait until the last phase.

| Order | Reviewable package | Reference and current seam | Acceptance before calling it complete |
| --- | --- | --- | --- |
| 1 | **Chat and question polish:** meaningful public process row, concise completion/outcome, useful artifact cards, Later/Show dock, contextual empty state/composer and correct Capabilities destination | Thread/full, [tool-call card](https://www.affectui.com/components/tool-call-card), [thinking state](https://www.affectui.com/components/thinking-state), [Inbox](https://www.affectui.com/screens/inbox); current Conversation/TurnProcess/questions/output/settings callers | Real Ask and Plan states; no duplicate generic groups; long question remains reviewable; drafts/focus survive collapse, task switch and failure; no auto-submit/approval. No fake streaming or success. |
| 2 | **Sourced project brief:** visible Brief & decisions, confirmed/proposed facts, source turn/task, scope and explicit supersession | Memory screen; existing task/agent_memory context and brief controls | Each fact backed by actual data. A stale handoff cannot overwrite newer project decisions. Read-only sourced context is an interim state, not completion of D20's editable persistent brief. No personal memory or fake save controls. |
| 3 | **Drafting and sheet separation:** dark2D world view, dark complementary3D, familiar pan/zoom/navigation, selection/properties, readable labels, measurement/annotation discovery; white Sheet/Print view | Official Revit navigation; current PlanCanvas/PlanDrawing/PlanThree and exact geometry guards | Preserve the shared PlanGraph identity, units and supported selection mapping; do not imply schematic3D is a native model. Pointer-centered zoom/Fit and keyboard/touch alternatives; same viewer survives tab/focus. Comments disclose local persistence and stale anchors. White exports remain legible. Review, not wall dragging. |
| 4 | **Deliverable and revision flow:** named concepts/reports, view/source/version, explicit revise brief, compare and export quality/provenance | [Change summary](https://www.affectui.com/components/change-summary), [review center](https://www.affectui.com/components/review-center), [data table](https://www.affectui.com/components/data-table), Streamdown interactivity | Real artifact opens from chat; failed revision retains the last usable artifact; current viewport capture and saved sheet/source distinguished. Correct CSV/PNG/PDF behavior tested where supported; no invented revision history or native save. D9 remains a backend gate. |
| 5 | **Secondary task/agent visibility:** task status and Needs-you overview, real agent results and plain scoped permissions | Tasks, Permissions, Orchestration; existing task list/runtime manifests/connection reviews | Actual scoped records and explicit unavailable states. No invented percent, fleet, editable rule persistence or hidden authority changes. Do not delay the primary concept experience to build an operational agent dashboard. |
| 6 | **Complete primary-journey qualification:** generate → clarify genuinely missing inputs → review2D/3D → request revision → compare → save/export | Canonical component map, approved exact approval guards, real routes | Do not repeat confirmed facts; group missing inputs and explain scope changes. Cover completion without an artifact, partial artifact, pending clarification and failed revision retaining the previous concept, plus success/reload/task-account isolation/narrow/keyboard states. Track UI parity, goal completion, source truth and native qualification separately. A passing unit suite alone is insufficient. |

Backend follow-up is a separate lane: confirmed brief/question semantics, authoritative outcomes/progress, project memory persistence, real child-agent/tool contracts, upload/derivative processing, immutable reports and native Revit version/read-back qualification. Do not select an APS/cloud architecture, install MCP servers/skills into the runtime, or enable unavailable controls during this UI planning phase.

An Astra High review of this proposal required the early contract gate, replacing an unrealistic “clarify once” guarantee, and tightening memory/viewer/revision acceptance. Those corrections are incorporated above. This review is not approval to implement the proposed packages or a formal EGM convergence claim.
