# Roadmap — connect the UI to the harness, then grow admin (16 November 2026)

Status: **proposed, awaiting user approval.** No application code has changed. This replaces the N1–N5 order in [AGUI_MIGRATION_PLAN.md](../agui/AGUI_MIGRATION_PLAN.md) and the "deferred" status of admin work, per decisions D22 and D23 in [PLAN.md](../../PLAN.md). Evidence behind it: [research record](research-reference-and-harness-2026-11-16.md). Each phase below becomes a full packet (from [PACKET_TEMPLATE.md](PACKET_TEMPLATE.md)) that the user approves before the phase starts.

## 2. Decisions taken (user, 16 Nov)

1. **Harness:** detect capabilities per backend; production orchestrator default.
2. **Backend code:** a fresh branch from `188ebc0`, with the candidate patches re-applied. Nothing is pushed or deployed.
3. **Admin scope:** traces and feedback, versioned config and audit, model registry, MCP and skills registry, all four.
4. **Model router:** deferred. Cheap rules first; a shadow experiment stays parked.

Parallel rule: a frontend and a backend phase may overlap only if they touch different repositories and agree the contract in the packet first. Two writers never share a file.

## 4. Phases

Standing gates for every phase: `npm run typecheck`, `npm test`, `npm run build`, `lat check`; for backend phases the domain-api test suite plus the backend's own post-change checks. Every phase ends with the checkpoint in [AGENTS.md](../../AGENTS.md#7-plan--build--checkpoint). "Rollback" means a revert of that phase's commits; contract changes are additive so old clients and paused v2 tasks keep working.

### S0 — Source verification and backend baseline

- **Goal:** a source-verified feature matrix, and a working backend checkout to build on.
- **Web (read-only):** classify every row of the handoff's "what exists" table as *tested*, *under-tested*, *controlled/local*, *planned* or *deferred* with `path:line`. Cover AG-UI adapter and transport, composition registry, process grouping, question resume.
- **Backend:** clone the candidate repository into a new folder, create a branch at `188ebc0` (proposed name `codex/web-ui-harness-20261116`), `git apply --check` then apply the two patches from `docs/backend-candidates/`, run the domain-api tests with the existing virtualenv, record the result. The frozen Plan-intent candidate and the paused alternative-count branch stay untouched and unmerged.
- **Acceptance:** matrix committed in the packet; backend baseline counts recorded (previous record: 180 tests + 26 subtests); both patches apply cleanly or the conflict is documented.
- **Risks:** patch drift; the candidate's `lat` graph freshness is unresolved, so do not run graph refresh.
- **Rollback:** delete the new checkout; nothing else changes.

### C1 — Capability contract and config consistency

- **Goal:** one signal the UI trusts to know what the connected backend can do, and a model list that cannot drift.
- **Backend (S):** `GET /v1/capabilities` returning a versioned document (service name and contract version, supported admin sections, tool and event features, limits). Make `/v1/config` serve the admin list; make v2 submit honor the admin default effort; define limit 0 explicitly. Tests beside `test_app_config.py` and `test_round3_api.py`.
- **Web:** `src/lib/capabilities.mjs` (+ `.d.mts`) parses and defaults conservatively; unknown means unsupported. Add `capabilities` to the proxy allow-list in `src/app/api/service/[...path]/route.ts` with a test in `tests/service-proxy.test.mjs`. Replace "Backend not deployed yet" guesses in `src/components/admin/use-admin.tsx` with capability checks. Model picker (`model-picker.tsx`) reads the corrected list.
- **Reuse:** existing `api()` helper in `use-workspace-state.ts`; `ui/` primitives for empty and unavailable states.
- **Contract:** additive endpoint; no event or checkpoint change.
- **Tests and browser:** unit tests for parsing and fallbacks; browser at 1280 and 390 px with the capability response mocked as orchestrator, OpenCode preview and unreachable.
- **Acceptance:** UI hides or explains any feature the backend does not report; picker equals admin list; gates green.
- **Risks:** a wrong default makes a feature look available; mitigate with "unknown = off".
- **Rollback:** revert; old UI ignores the endpoint.

### N1 — Durable completion proof

- **Goal:** answers keep their validated presentation after the 2,000-event tail evicts old events.
- **Backend (M):** store each answer's completion and presentation projection in its own collection keyed by owner, task, turn, execution and content hash (`storage.py`, `chat_composition.py`, `task_events.py`), written at completion, read by the projection. No backfill of old answers; they keep the literal answer.
- **Web:** `src/lib/chat-composition.mjs` and `conversation-turns.mjs` read the durable projection; the client hash and identity gate stays.
- **Contract:** additive field or endpoint; v2 compatibility test with a paused task.
- **Tests and browser:** backend tests for eviction, foreign owner, stale hash, failed validation; web replay test; browser: reload an old composed answer after eviction (fixture), 390 px.
- **Acceptance:** old answers retain correctly bound presentation; stale, foreign or failed results are denied; no repeated commands.
- **Risks:** storage growth (bound size per answer); mismatched hashing between Python and JS (reuse the 12 shared vectors).
- **Rollback:** feature flag off falls back to tail-derived behavior.

### N3 — Tool, task and sub-agent lifecycle

- **Goal:** the process UI shows real tool timing, outcome and parent/child agents instead of unconfirmed labels.
- **Backend (M):** add `durationMs` and `outcome` to the public event allowlist (`storage.py` `public_event`) and emit them from tool producers; add specialist start, progress and end events (`specialist_jobs.py`). Additive; old events lack the fields.
- **Web:** map new fields to AG-UI `TOOL_CALL_START/END` and `STEP_STARTED/FINISHED` in `src/lib/agui/adapter.mjs`; `turn-nesting.mjs` and `process-activity.mjs` use them; keep "unconfirmed" when a field is absent; `workspace/turn-process.tsx` shows timing.
- **Reuse:** vendored `tool-call-card-clean.tsx`, `ai-elements/tool.tsx`, existing grouping.
- **Tests and browser:** backend event-shape tests; web adapter and nesting tests with old and new events; browser: a tool failure, a retry, two concurrent specialists, interrupt and resume.
- **Acceptance:** concurrent agents, failures, retries and interruption are distinguishable; no private reasoning shown; old tasks render as before.
- **Risks:** event volume against the 200 inline / 2,000 tail caps; keep fields small.
- **Rollback:** adapter ignores new fields.

### N2 — Frontend capability awareness and reversible actions

- **Goal:** the agent knows the current chat, selected context, supported presentation primitives and viewport class, and can trigger only allowlisted reversible display actions.
- **Web:** `src/lib/agui/capabilities.mjs` builds a bounded, versioned envelope (no DOM, no logs, no secrets); `adapter.mjs` sends it with the run; actions limited to display operations (open a work-area tab, expand a disclosure, scroll to a turn, prefill the composer draft) validated against the current task and epoch.
- **Backend (S):** accept the envelope as optional input; expose allowed actions as frontend tools (AG-UI tool calls).
- **Contract:** additive request field; consequential operations stay server-authorized and never come from this channel.
- **Tests and browser:** stale-scope action denied; unknown action denied; undo for each action; browser at 390 px.
- **Acceptance:** actions are reversible, scoped to the current task, logged in the process list; native approval untouched.
- **Risks:** prompt injection through displayed content; actions never read model text as authority.
- **Rollback:** envelope flag off.

### A1 — Traces and feedback

- **Goal:** admins see text-free per-turn traces; users can rate an answer; the two join.
- **Backend (M):** read-only `GET /v1/admin/traces` (period, filters) built from `model_call_telemetry` and N3 fields: owner hash, requested and served model, outcome, steps, tools, signals, tokens, USD, duration. No question or answer text. `POST /v2/tasks/{id}/feedback` (up or down, reason enum, optional note, opt-in text sharing) joined by task and turn.
- **Web:** `/admin/traces` and `/admin/feedback` pages in the existing admin shell using `form.tsx` and `data-sections.tsx` patterns; thumbs control in `workspace/conversation-answer.tsx` using vendored `message-actions-clean.tsx`; proxy allow-list entries and tests; capability gate from C1.
- **Reference:** Panda-agent text-free trace and feedback design (see research record), minus its manual eval copy step.
- **Tests and browser:** privacy test that no text fields appear; filter and period tests; browser: submit feedback, see it joined in admin (fixture).
- **Acceptance:** traces contain no user text; feedback is owner-scoped and opt-in for text; admin-only access enforced by backend.
- **Risks:** privacy (hash owner ids, no text); new collection retention policy to decide.
- **Rollback:** pages hidden by capability flag.

### A2 — Versioned config and audit

- **Goal:** every config change has history, a readable audit entry and a restore.
- **Backend (S–M):** keep compare-and-set; add a history collection of full snapshots per revision, richer audit rows (what changed, before/after hash, paging), `POST /v1/admin/config/restore` that creates a new revision.
- **Web:** history and restore panel in the admin config pages; audit page paging and filters; 409 handling already exists in `use-admin.tsx`.
- **Reference:** Panda-agent versioned rows with conflict errors, plus the restore action Panda lacks.
- **Tests and browser:** restore creates a new revision; stale restore returns 409; browser: edit, conflict, restore.
- **Acceptance:** restoring never rewrites history; runs keep their snapshot.
- **Rollback:** new endpoints unused if reverted.

### N4 — Evidence-backed compositions and versioned interactions

- **Goal:** compositions can cite immutable report revisions and measurements by identity, and interactions carry versions.
- **Web:** extend the bounded registry (metric, checklist, choice or form) in `src/lib/chat-composition.mjs` and `workspace/chat-composition.tsx`; references resolve only to saved revisions with exact id and hash; invalid specs fall back to the full answer.
- **Backend (S–M):** extend the finish-tool schema and validation (`chat_composition.py`); measure schema bytes (previous record: +1,489).
- **Contract:** additive; no executable content.
- **Tests and browser:** the 12 shared Python/JS vectors extended; browser replay fixture; live-provider quality stays unqualified until G1.
- **Acceptance:** wrong or foreign references are rejected; versioned questions keep authority; full-answer fallback proven.
- **Risks:** tool-schema growth costs tokens; measure before enabling by default.
- **Rollback:** flag falls back to current registry.

### Q1 — Rules pre-router and latency measurement

- **Goal:** measure where each turn spends time and money, then add only deterministic shortcuts.
- **Backend (S):** per-phase timings recorded as trace signals; a LangGraph conditional edge for greetings and small talk (short path, no tools) with hard floors: attachments, approvals, resumed runs and anything needing evidence always take the full path. Rules, no model call.
- **Reference:** Panda-agent `fast-lane/router.ts` approach and its finding that metadata fetches, serial setup, resent schemas and re-prompts dominate cost, not routing.
- **Tests:** table-driven routing tests; a regression set of questions that must stay on the full path.
- **Acceptance:** measured before/after on a fixed question set; no domain question reaches the short path.
- **Parked, not planned:** a model router (the TypeSafe decision model or any other). Reconsider only with a labelled set of at least 200 questions from two raters, a vendor and privacy review, a stable non-alpha API, and gates borrowed from Panda's plan (95% lane accuracy on acted turns, at most 2% false history drops, zero injection reaching the short path), run first in shadow mode with no effect on any turn.

### A3 — Model registry

- **Goal:** admins add, test, enable and scope models with usage visible.
- **Backend (M):** `POST /v1/admin/models/test` (latency, tool-call check), per-model daily usage aggregate from telemetry, per-model visibility flag; new models default to off until tested and enabled.
- **Web:** `/admin/models` with a stats strip, ordered list, test modal and usage table using `ui/` and vendored table patterns; mobile `data-label` tables.
- **Reference:** Panda-agent `/admin/agent-models` layout and its "off until tested" rule. Its OpenRouter credit banner applies only if DATUMM uses OpenRouter credit.
- **Acceptance:** a model cannot serve users before a passing test and an enable; usage totals match telemetry.
- **Open question:** user groups for visibility (today there is one admin role); see section 6.

### W1 — Right work area on AG-UI state

- **Goal:** Activity, Assets and Exports read the same AG-UI event and state stream as the chat.
- **Web:** feed `inspector.tsx` sections from `STATE_SNAPSHOT` and delta events instead of separate polling where the backend provides them; keep one mounted drawing and exact-identity bindings.
- **Out of scope:** floor-plan shared state, direct editing, import. Needs its own approval before starting.
- **Acceptance:** no regression of the qualified Design/Activity/Assets/Exports journeys; fewer polling loops.

### A4 — MCP and skills registry

- **Goal:** admin-registered MCP servers and skills that the agent can actually use, safely.
- **Backend (L):** MCP client using the official Python SDK; sealed secrets with the server name bound to the ciphertext; HTTPS only, SSRF blocklist, 15 s timeout, response size caps; test-before-enable; per-tool allow, ask or never with risk classes; Revit write tools always ask. Skills: SKILL.md validation, per-mode scope, version history. Tool set snapshotted per run so resumed v2 checkpoints keep their original tools.
- **Web:** `/admin/mcp` and `/admin/skills` extended with test, per-tool modes, SKILL.md editor with live validation; clear "stored only" label removed only when the backend reports live MCP.
- **Reference:** Panda-agent `mcp/secret.ts`, `mcp/client.ts`, `skill-md.ts`, `approvals.ts`, `skills-registry.tsx`, `mcp-registry.tsx` as design input, not code to copy (TypeScript and a hand-written client). Panda's own gaps to avoid: no OAuth, DNS re-check only at save and test, skill history with no restore.
- **Risks:** highest of any phase: untrusted tool output, secrets, checkpoint compatibility, token cost of tool schemas. Needs a security review and a separate packet approval.
- **Acceptance:** a disabled or untested server cannot be called; secrets never reach the browser; resumed tasks unaffected.
- **Rollback:** feature flag; tool set reverts to the fixed allowlist.

### N5 — Provider streaming and measured performance

- **Goal:** useful partial updates sooner, without weakening answer admission.
- **Backend (L):** flagged AG-UI-shaped projection with provider token streaming; evidence admission and correction happen before publication or a visible retraction path exists.
- **Web:** handle `TEXT_MESSAGE_CONTENT` deltas and reconnection in `agui-chat-transport.ts`; no silent fallback that resubmits an admitted command.
- **Measurements:** time to first acknowledgment, time to first useful update, render cost, transport size, memory, tokens, against the Q1 baseline. No savings are claimed without these numbers.
- **Acceptance:** truncated connections never synthesize success; measured results recorded before any claim.

### G1 — Hosted gate

Access-dependent and not startable now (AWS login unavailable). Deploy and validate the backend branch, real Mongo and container tests, a live provider, checkpoint compatibility with paused v2 tasks, rollout and rollback, then the Plan general question and generate → revise → report → reload journeys. Requires the user's explicit approval for any deployment.

## 5. Practices that apply to every phase

- **Plan first:** packet approved before code; questions go to the user in batches with a recommendation.
- **One owner per file;** implementer and reviewer are different agents; the orchestrator re-runs the gates itself (see [CLAUDE.md](../../CLAUDE.md)).
- **Additive contracts;** nothing changes the v2 command schema, existing event meaning or checkpoint shape without a compatibility test on a paused task.
- **Evidence labels:** observed vs inferred; local, controlled or hosted; never claim an unrun check.
- **Components:** reuse `ui/` and vendored affectUI; reconstruct Pro previews independently; follow [DESIGN.md](../../DESIGN.md).
- **Native authority** never flows from composition, navigation, Markdown or a capability signal.
- **Checkpoint:** results into the packet, handoff overwritten, [PLAN.md](../../PLAN.md) row updated, commit.
