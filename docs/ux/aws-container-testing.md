## Why a test-only override is required

The repository's historical `infra/orchestrator/builder.buildspec.yml` builds **and pushes** an image to ECR. It must not run unchanged. The envelope's `buildspec-test.yml` is a separate override that only invokes the local test runner; it contains no ECR login, push, deployment, or CloudFormation command. AWS documents that a buildspec override applies to one build, and that an S3 input's source version is the object version ID. Verify actual IAM/source/override permission and pin the reviewed envelope's S3 object version before dispatch; do not assume the existing role can read a chosen object or that its defaults are safe. [AWS StartBuild reference](https://docs.aws.amazon.com/cli/latest/reference/codebuild/start-build.html), [CodeBuild environment source versions](https://docs.aws.amazon.com/codebuild/latest/userguide/build-env-ref-env-vars.html).

The historical builder uses Docker with a daemon and may require privileged mode, depending on its network environment. Confirm the actual existing project's build environment and ability to pull the pinned base images and packages before use. Do not change IAM or provision a new project, host, bucket, network, secret or service to make this test possible. Docker build needs network access to its pinned base image references and the existing `npm ci` / `uv sync` dependency sources; offline runtime tests below do not establish a fully hermetic build. [AWS CodeBuild runtime privilege guidance](https://docs.aws.amazon.com/codebuild/latest/userguide/sample-docker-custom-image.html).
