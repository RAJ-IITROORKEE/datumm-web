# Phase 1–2 contract review

Source review, 13 November 2026. This records frontend types and existing usage, not a claim that every hosted task contains these optional fields or that backend behavior was independently verified.

## Phase 2 source contract

- `Run` in `src/components/workspace/use-workspace-state.ts` is the selected task snapshot. It carries `id`, optional `projectId`, `taskVersion`, `eventCursor`, `title`, `status`, and optional `data`. These identify the source snapshot; they do not independently establish the age or completeness of each nested field.
- `agent_interpreted_brief` contains `status`, `dimensions` (`sourceText`, `role`, nullable width/depth in mm), `values` (key, value, provenance string), `unresolved`, `assumptions`, nullable program booleans and optional policy. The TypeScript type does not define a provenance/status enum or a per-item confirmation flag. Present values and raw provenance as task interpretations, assumptions as assumptions, and unresolved items as unresolved. Do not convert arbitrary provenance strings, dimension roles, booleans or lifecycle status to confirmed decisions.
- `agent_memory` is a task handoff, with schema/version, original goal, unknown-shaped answer groups, document binding, evidence summary, unresolved operations and next action. Its `answers: unknown[]` cannot safely be turned into individual decisions without a supported schema. Its version is a task-handoff version, not a project-memory version.
- `agent_draft`/`draft_task` contains requested goal, fingerprint, proposed changes, criteria and optional preview. It is a proposal, not evidence of acceptance or native execution. `agent_design.brief` and legacy `plan.brief` describe plan data; do not claim they are confirmed inputs. Existing `acceptance` binds accepted assumptions to a specific plan ID/version/fingerprint. That narrow plan approval cannot be generalized to all task facts.
- Project metadata (`ProjectRow`) consists of id, title, optional chat count, revision, default and archive fields. It does not expose a persistent brief or project-decision mutation contract. `project_context_shared` is a flag, not a project brief payload. There is no established global personal memory contract.

A minimal read-only projection should consume the current selected `Run | null`, selected task identity, the current project identity/title including explicit default handling, and a draft-only amendment callback; dialog open/change remain UI props. Bind the run to the selected task before display and verify project association where known. Treat unresolved or missing associations as unknown, not as proof of ownership. Do not combine sources by precedence: retain separate source labels and display conflicting values independently; no silent supersession. Show available task version, event cursor, handoff version, and plan fingerprint/version only beside the source they identify, and explain freshness is not established where it is not. Missing/partial payloads should render an honest empty/partial state. If the task changes while the dialog is open, replace the projection synchronously rather than retaining the prior task's content; the amendment callback must target the current task's existing scoped composer draft, preserve existing text and never submit or claim a save.

## Phase 1 review

Review in progress. The question forms remain mounted while collapsed and their hidden CSS removes descendants from layout and focus. Hosted drafts are scoped to task/question/version in session storage; native answers are in-memory and reset on unmount. Process labels preserve failed and unconfirmed states and keep the checklist separate from worker evidence. Two findings were sent to the integrator:

1. A concept reference or candidate count alone does not establish that a current drawing is available; the no-artifact recovery must not be suppressed solely by either. A proposed recovery prompt also assumed confirmed dimensions without source evidence.
2. The existing hosted lost-response receipt recovery compared only question ID, although the receipt and payload both carry a version. A stale same-ID receipt can be mistaken for an accepted newer answer. Match both ID and version before clearing answers.

Reinspection found both fixes in source: the recovery receipt now checks task ID, question ID and version; the concept check uses exact current drawing identity, and the prompt no longer assumes confirmation. The drawing can still be loading when that identity is unavailable; the integrator was advised to avoid a premature missing-drawing message and avoid implying turn-level provenance. Browser validation remains with the integrator.

Final Phase 1 review found no remaining source blockers. The settled-result copy uses renderable drawing availability (including explicitly labeled retained alternatives), suppresses missing-drawing copy while loading, and does not claim a specific response produced a new revision. Actual browser verification is recorded in the execution packet.

## Phase 2 review

The integrator resolves project context only from the selected task's actual project ID, including a matching default project. It never uses the new-draft fallback as ownership proof. Task interpretations and handoff remain separate; unknown answer payloads are omitted and plan acceptance remains narrowly identity-bound.

Review corrections: draft updates preserve the existing mode and text, reject stale task/account/draft-owner callbacks and active tasks, and are disabled for pending hosted questions and displayed OpenCode questions (including lagging lifecycle snapshots). This prevents a brief update from being routed as a single pending-question answer. Partial current plan references must produce an unknown relationship, not a different-plan claim. Source and interaction tests cover these boundaries. Browser checks include the real conflicting footprint/parcel audit snapshot, matched Clinic studies context, no-task empty state, narrow layout, draft-only focus handoff and ordinary Escape focus restoration. Project-wide editing/persistence is still unavailable.
